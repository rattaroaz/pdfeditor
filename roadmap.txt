PDF Editor — Adobe Acrobat Clone Roadmap
==========================================
Target: ~90% of common Acrobat functionality
Stack: TypeScript, Tauri 2, React, Rust backend
Quality bar: Production-ready, full test coverage, structured logging

Legend: [ ] = not started   [x] = complete


================================================================================
PHASE 0 — PROJECT FOUNDATION & REPOSITORY SETUP
================================================================================
Establish the monorepo, tooling, and conventions before any feature work.

[x] Initialize Tauri 2 app with TypeScript frontend (Vite + React)
[x] Initialize Rust workspace for Tauri commands and native PDF operations
[x] Configure ESLint, Prettier, and strict TypeScript (strict: true)
[x] Set up path aliases, env handling (.env.example), and secrets policy
[x] Choose and integrate UI component library (e.g. Radix + Tailwind or shadcn/ui)
[x] Define folder structure: src/ (frontend), src-tauri/ (Rust), shared/ (types)
[ ] Add conventional commits, PR template, and CODEOWNERS
[x] Set up GitHub Actions (or equivalent CI): lint, typecheck, test, build
[x] Document local dev setup in README.md (prerequisites, npm run tauri dev)
[x] Add LICENSE and CONTRIBUTING.md


================================================================================
PHASE 1 — LOGGING, ERROR HANDLING & OBSERVABILITY (FOUNDATION)
================================================================================
Logging and error infrastructure must exist from day one — not bolted on later.

[x] Frontend: integrate structured logger (e.g. pino or winston) with log levels
[x] Rust: integrate tracing + tracing-subscriber with JSON/text formatters
[x] Define log context fields: sessionId, documentId, userAction, durationMs
[x] Implement log rotation and max file size for desktop log files
[x] Add Tauri command wrapper that logs invoke start/end/errors uniformly
[x] Global error boundary (React) + unhandled rejection / panic handlers (Rust)
[x] User-facing error toast/dialog with copyable error ID for support
[ ] Optional: crash report hook (Sentry or similar) behind feature flag
[x] Dev-only log viewer panel in app settings

Test harness and patterns established before core features land.

[ ] E2E tests: Playwright or WebDriver targeting Tauri webview

================================================================================
PHASE 3 — PDF RENDERING ENGINE (CORE VIEWER)
================================================================================
The heart of the app: fast, accurate PDF display.

[x] Evaluate and select PDF library:
      Option A: pdf.js (Mozilla) in frontend for rendering
      Option B: pdfium (Rust) rendered to canvas via Tauri
      Option C: Hybrid — pdf.js view + Rust for mutations
[x] Implement page renderer: canvas or WebGL, DPI-aware scaling
[x] Zoom: fit page, fit width, actual size, custom % (25–6400%)
[x] Pan/scroll with momentum; middle-mouse and space+drag pan
[x] Continuous scroll vs single-page vs two-page spread modes
[ ] Page cache and prefetch (N pages ahead/behind)
[x] Thumbnail sidebar with lazy generation
[x] Loading states, progress for large files, cancel in-flight render
[ ] Render tests: compare output against reference images per zoom level

================================================================================
RECOMMENDED BUILD ORDER (DEPENDENCY GRAPH)
================================================================================
  Phase 0 → 1 → 2 (parallel foundation)
       ↓
  Phase 3 (viewer) → 4 (files) → 5 (navigation) → 6 (search)
       ↓
  Phase 7 (annotations) → 8 (pages) → 9 (edit) → 10 (forms)

Logging (Phase 1) and tests (Phase 2) run continuously — add tests for each
feature before marking its phase items complete.


================================================================================
KEY TECHNOLOGY DECISIONS (TO RESOLVE IN PHASE 0)
================================================================================
| Concern              | Recommended starting point                          |
|----------------------|-----------------------------------------------------|
| UI framework         | React 18 + TypeScript + Vite                        |
| Desktop shell        | Tauri 2                                             |
| PDF render           | pdf.js (fast path) + Rust lopdf/qpdf for mutations  |
| PDF write/edit       | lopdf or pdfium-rs in src-tauri                     |
| OCR                  | Tesseract (tesseract-rs)                            |
| State management     | Zustand or Jotai                                    |
| Frontend tests       | Vitest + Testing Library + Playwright               |
| Rust tests           | cargo test + cargo-fuzz                             |
| Logging (TS)         | pino with file transport                            |
| Logging (Rust)       | tracing + tracing-appender                          |
| CI                   | GitHub Actions                                        |

================================================================================
OUT OF SCOPE (EXPLICIT NON-GOALS FOR v1)
================================================================================
- Real-time collaborative editing (Google Docs-style)
- Full PDF/X preflight and print production
- Complete JavaScript Acrobat API compatibility
- XFA dynamic forms (legacy; show "unsupported" message)
- 3D PDF and CAD viewer
- DRM / RMS enterprise rights management
- Mobile iOS/Android native apps (desktop Tauri only for v1)
